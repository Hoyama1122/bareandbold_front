เอกสารอธิบายการออกแบบระบบ (System Design Documentation)
ระบบร้านค้าออนไลน์และออกแบบคัสตอมสร้อยข้อมือ Bare & Bold

เอกสารนี้รวบรวมหน้าที่และความสำคัญของแผนภาพและเครื่องมือออกแบบระบบต่าง ๆ ที่สอดคล้องกับระบบร้านค้าออนไลน์และบริการออกแบบคัสตอมสร้อยข้อมือ Bare & Bold ในปัจจุบัน

========================================================================

1. Use Case Diagram (แผนภาพการใช้งานระบบ)
หน้าที่และความสำคัญสำหรับระบบ Bare & Bold:
แสดงขอบเขตการทำงานของระบบร้านค้าออนไลน์และจำลองฟังก์ชันหลักของแต่ละกลุ่มผู้ใช้งาน ปฏิสัมพันธ์เกิดขึ้นระหว่าง Actors ทั้ง 4 บทบาทหลัก ได้แก่:
- ผู้ใช้งานทั่วไป (Guest): สามารถเข้าเรียกดูสินค้า, ค้นหาสินค้า และดูรายละเอียดสร้อยข้อมือ
- ลูกค้าสมาชิก (Customer): สมัครสมาชิก, เข้าสู่ระบบ, เข้าใช้ฟังก์ชันออกแบบสั่งคัสตอมสร้อยข้อมือ (Customizer), จัดการตะกร้าสินค้า, ดำเนินการชำระเงินออนไลน์ (Checkout) และติดตามสถานะจัดส่งสินค้า
- พนักงาน (Staff): ตรวจสอบและยืนยันคำสั่งซื้อ, ปรับปรุงสต็อกวัตถุดิบและชิ้นส่วนสร้อยคัสตอม, จัดการสถานะจัดส่ง
- ผู้จัดการระบบ (Manager / Admin): เพิ่ม/แก้ไข/ลบสินค้าและตัวเลือกวัตถุดิบ, จัดการบัญชีผู้ใช้งาน, เข้าดูรายงานสรุปยอดขายบน Dashboard
* พร้อมการเชื่อมต่อภายนอก (Secondary Actors) เช่น ระบบชำระเงิน Omise Gateway และ Mock Shipping API เพื่อจำลองสถานะการส่งพัสดุ

แผนภาพนี้ช่วยให้ทีมพัฒนาและ Tester ทราบว่าผู้ใช้แต่ละคนมีสิทธิ์เรียกใช้ Endpoint หรือฟังก์ชันใดในระบบหน้าร้านได้อย่างถูกต้อง

------------------------------------------------------------------------

2. Class Diagram (แผนภาพคลาส)
หน้าที่และความสำคัญสำหรับระบบ Bare & Bold:
แผนภาพโครงสร้างสถาปัตยกรรมภายในของแอปพลิเคชันฝั่ง Frontend และโครงสร้างโมเดลหลักที่ใช้ในการทำงาน เช่น:
- คลาสข้อมูล (Entities/Models): User (เก็บโปรไฟล์ลูกค้าและบทบาท) และ Product (เก็บรายละเอียดข้อมูลสินค้า/ชิ้นส่วนคัสตอม ราคา รูปภาพ)
- คลาสบริการ (Services): AuthService (รับผิดชอบเรื่อง Login/Register) และ ProductService (ยิง API ไปดึงรายการสินค้าจากหลังบ้าน)
- คลาสจัดการสถานะ (React Hooks): UseAuth (เก็บ State ของผู้ใช้เพื่อแชร์ทั่วทั้งเว็บ)
- คลาสคอมโพเนนต์ (React Components): StorefrontPage, Header, AuthModal และ ProductCard

เป็นพิมพ์เขียวสำคัญที่อธิบายโครงสร้างตัวแปร คุณสมบัติ (Attributes) ความเชื่อมโยงแบบองค์ประกอบ (Composition/Aggregation) และฟังก์ชัน (Methods) ซึ่งช่วยให้ Backend Developer นำไปวางโครงสร้างฐานข้อมูล PostgreSQL และกำหนด Entity/Schema ในตัวโปรแกรมได้อย่างแม่นยำ

------------------------------------------------------------------------

3. Sequence Diagram (แผนภาพแสดงลำดับขั้นตอนการทำงาน)
หน้าที่และความสำคัญสำหรับระบบ Bare & Bold:
แสดงลำดับการรับส่งข้อความ (Message Passing) หรือลำดับการทำงานตามแกนเวลาเพื่อสะท้อนพฤติกรรมจริงของระบบ ตัวอย่างขั้นตอนสำคัญในระบบปัจจุบัน:
1) ลูกค้าออกแบบคัสตอมและกดสั่งซื้อ -> หน้าร้านส่งคำขอ POST /api/orders
2) API Backend บันทึกออเดอร์สถานะ "Pending" ลงฐานข้อมูล Neon (PostgreSQL)
3) ระบบเชื่อมต่อกับ Omise Payment Gateway เพื่อชำระเงินออนไลน์ (PromptPay/QR Code)
4) เมื่อชำระเงินสำเร็จ อัปเดตออเดอร์เป็นสถานะ "Paid" และส่งคำสั่งอัปเดตสต็อกวัตถุดิบ
5) พนักงานเข้าหน้า Backoffice เพื่อตรวจสอบออเดอร์และส่งอัปเดตเลขพัสดุผ่าน API ขนส่งจำลอง (Mock Shipping API)

ช่วยให้ Backend Developer วางโครงสร้างสถาปัตยกรรม RESTful API และ Endpoint ได้สอดคล้องกับพฤติกรรมของหน้าร้าน และทำให้ Frontend Developer รู้ขั้นตอนการยิง API และสลับหน้า UI ตามลำดับ

------------------------------------------------------------------------

4. Wireframe (โครงร่างหน้าตาแอปพลิเคชัน)
หน้าที่และความสำคัญสำหรับระบบ Bare & Bold:
โครงร่างลายเส้นแบบหยาบ (Low-fidelity) ที่วางเลย์เอาต์หน้าจอหลักของเว็บ เช่น หน้าแรกที่มีเมนูจัดหมวดหมู่ แผงควบคุมระบบปรับแต่งสร้อยข้อมือ (Customization Studio) ที่ต้องวางการแสดงภาพ 2D/3D จำลองสร้อย, แถบตัวเลือกวัสดุ (ลูกปัด, จี้, หินนำโชค) และส่วนจัดการระบบ Dashboard ของแอดมิน 

ช่วยให้ทีมงานมุ่งเน้นไปที่การออกแบบประสบการณ์ผู้ใช้ (UX), ลำดับการแสดงข้อมูล (Information Architecture) และการเข้าถึงฟังก์ชันสำคัญต่าง ๆ โดยไม่ต้องกังวลเรื่องสีสัน ฟอนต์ หรือรูปภาพสวยงามในขั้นตอนแรก

------------------------------------------------------------------------

5. Prototype (แบบจำลองการใช้งานจริง)
หน้าที่และความสำคัญสำหรับระบบ Bare & Bold:
แบบจำลองที่มีความละเอียดสูง (High-fidelity Interactive Design) เช่น การใช้ Figma Prototype หรือเว็บทดลองเพื่อให้ผู้ใช้ทดลองคลิกเลือกประเภทจี้ เลือกหินมงคล ลากวางชิ้นส่วน จำลองสร้อยข้อมือ แล้วทดลองกดปุ่มหยิบลงตะกร้า ไปจนถึงการกดหน้าชำระเงินจำลอง

ช่วยให้ Frontend Developer ทราบดีไซน์ ขนาดขอบ ระยะห่าง (Padding/Margin) โทนสี และสามารถเปลี่ยนสไตล์เหล่านั้นให้อยู่ในรูปของ CSS หรือ TailwindCSS ได้ง่าย รวมถึงทำให้ได้ Feedback รวดเร็วจากลูกค้าและผู้มีส่วนเกี่ยวข้องก่อนพัฒนาซอฟต์แวร์จริง
