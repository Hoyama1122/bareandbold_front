คำถาม 3: การวิเคราะห์ปัญหาและการทดสอบระบบ (Troubleshooting & Performance Testing)

1. เครื่องมือที่เลือกใช้: Apache JMeter ร่วมกับ Chrome DevTools (Network Tab)

2. ขั้นตอนการดำเนินงานเพื่อค้นหาสาเหตุ:
2.1 Replicate ปัญหาด้วย JMeter: ตั้งค่า Thread Group ใน JMeter จำลองผู้ใช้งานพร้อมกัน 50 - 100 คน (Number of Threads: 100, Ramp-up: 10 วินาที, Loop Count: 5 รอบ) ยิงคำขอไปยัง Endpoint ที่คาดว่ามีปัญหาและใช้ทรัพยากรสูงของระบบ Bare & Bold (เช่น /api/orders สำหรับการสร้างคำสั่งซื้อคัสตอม หรือ /api/products สำหรับการดึงข้อมูลรายการสินค้าทั้งหมด)
2.2 วิเคราะห์ข้อมูลจาก Summary Report: สังเกตค่า Average Response Time ว่าพุ่งสูงขึ้นผิดปกติขณะที่มีการทำธุรกรรมพร้อม ๆ กันหรือไม่ และตรวจสอบอัตรา Error % เพื่อดูว่าเกิดปัญหา Timeout หรือ HTTP Status 500 (Internal Server Error) จาก Backend หรือไม่
2.3 ตรวจสอบระดับโค้ดด้วย Browser DevTools: เปิดหน้าเว็บบนเบราว์เซอร์ สังเกตแท็บ Network เพื่อดูว่า API ชุดใดที่ใช้เวลาในการรอนานที่สุด (Waiting time - TTFB สูง เช่น ตอนโหลดหน้าแต่งสร้อยข้อมือคัสตอม หรือยืนยันจ่ายเงินผ่าน Omise Gateway) เพื่อระบุจุดที่เป็นคอขวด (Bottleneck) ของส่วนหน้าร้าน

3. แนวทางการแก้ไขเบื้องต้น:
- Database Optimization: ปัญหาส่วนใหญ่เกิดจากคำสั่ง Query ข้อมูลซ้ำซ้อนหรือขาดการทำ Indexing ในระบบฐานข้อมูล PostgreSQL (Neon) ให้ทำ Index บนฟิลด์ที่ถูกค้นหาและเชื่อมโยงบ่อย ๆ (เช่น order_id, user_id, product_id)
- Caching Strategy: นำระบบ Caching เช่น Redis มาใช้เก็บข้อมูลของระบบที่มีการเรียกใช้งานบ่อยแต่ไม่มีการเปลี่ยนแปลงถี่ (เช่น รายการสินค้าหน้าร้าน Catalog Product, ตัวเลือกชิ้นส่วนคัสตอมของสร้อยข้อมือ เช่น ลูกปัดหรือจี้ประเภทต่าง ๆ) เพื่อลดภาระการ Query จาก Database โดยตรง
- Asynchronous Processing: ปรับปรุงขั้นตอนที่ใช้เวลานานและต้องประสานงานกับระบบภายนอก เช่น การรับ Webhook และส่งอีเมลยืนยันคำสั่งซื้อ/ใบเสร็จ (Order Confirmation Email) ให้ทำงานเป็นฉากหลัง (Background Job Queue) แทนการประมวลผลแบบ Synchronous เพื่อไม่ให้บล็อก Request และลดการหน่วงเวลาการตอบสนองต่อผู้ใช้งาน
